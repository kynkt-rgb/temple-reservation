## 1. 背景と目的

### 1.1 背景

- 檀家さんからの法要予約は電話で受け付けている。
- 予約は **紙のカレンダー** と **Googleカレンダー** の両方で管理しており、次の問題が起きている。
  - 二重管理になり、片方への記入漏れや内容の食い違いが出る。
  - 空き状況をひと目で確認できず、同じ時間枠に予約が重なる。

### 1.2 目的

- 予約情報を1つのシステムにまとめ、**唯一の正しい予約台帳** とする。
- 予約ルール（法要は1枠1件、葬儀は1日1件など）をシステムで自動チェックし、**予約の重複を防ぐ**。
- 電話を受けながらでも、月全体の空き状況をすぐ確認できるようにする。

---

## 2. 利用者

| 利用者 | 説明 | 本リリースでの扱い |
| --- | --- | --- |
| お寺の職員 | 電話で予約を受け、登録・変更・削除を行う | 対象 |
| 檀家さん | 法要を依頼する人 | **対象外**（システムは操作しない） |

- 本リリースにはログイン機能がないため、システムにアクセスできる人は全員同じ権限を持つ。
- 利用端末は寺務所のPC（ブラウザ）を想定する。

## 3. 用語の定義

| 用語 | 意味 |
| --- | --- |
| 法要 | 四十九日・一周忌・三回忌などの仏事。本システムの主な予約対象。 |
| 葬儀の押さえ | 葬儀のために時間枠を仮に確保しておく登録。詳細管理はしない。 |
| 施主 | 法要を主催する人（予約の依頼者）。 |
| 時間枠 | 1時間単位の予約の区切り。開始時刻で呼ぶ（例：「10時枠」）。 |
| 場所 | 法要を行う場所。基本は「お寺」。総代さんに限り「自宅」も選べる。 |
| 総代 | 檀家さんの代表者。特例として自宅で法要を行える。 |
| 担当 | 法要を務める僧侶。「住職」または「副住職」。 |

## 4. 業務フロー

### 4.1 現状（As-Is）

1. 檀家さんから電話を受ける。
2. 紙のカレンダーで空きを確認する。
3. 紙のカレンダーに記入する。
4. あとでGoogleカレンダーにも入力する（ここで漏れ・食い違いが起きる）。

### 4.2 導入後（To-Be）

1. 檀家さんから電話を受ける。
2. アプリの月カレンダーで空き枠を確認する。
3. その場で予約を登録する。ルールに反する場合はエラーで知らされる。
4. 変更・キャンセルの電話があれば、施主名で検索して編集・削除する。

## 5. 機能要件

### 5.1 機能一覧

| ID | 機能 | 概要 |
| --- | --- | --- |
| F-01 | 月カレンダー表示 | 1か月分の予約状況を一覧表示する |
| F-02 | 法要予約の登録 | 新しい法要予約を登録する |
| F-03 | 法要予約の編集 | 登録済みの法要予約を変更する |
| F-04 | 法要予約の削除 | 登録済みの法要予約を削除する |
| F-05 | 葬儀の押さえの登録・編集・削除 | 葬儀用に時間枠を確保する |
| F-06 | 施主名検索 | 施主名で法要予約を探す |
| F-07 | 予約ルールのチェック | 登録・編集時にルール違反を防ぐ |

### 5.2 F-01 月カレンダー表示

- 1か月分を **見開き（1画面）** で見渡せる表示にする。スクロールなしで月全体の空き状況が分かることを目標とする。
- 表示形式：縦軸を日付（1日〜月末）、横軸を時間枠（10〜15時）とする一覧表形式を基本とする。
  - 曜日を表示し、土曜・日曜・祝日は色を変えて区別できるようにする。
- 各セル（日付×時間枠）に次の内容を表示する。
  - 法要：施主名、法要の種類、場所（お寺／自宅）、担当、食事の有無
  - 葬儀の押さえ：「葬儀」と分かる表示（色・ラベルで法要と区別する）
- 空いている枠は見た目で分かるようにする。
- 前月・翌月への移動、「今月」に戻る操作ができる。
- 空きセルをクリックすると、その日付・時間枠が入力済みの状態で登録画面を開く。
- 予約をクリックすると、その予約の編集画面を開く。

### 5.3 F-02 法要予約の登録

入力項目は「6.1 法要予約」のとおり。

- 必須項目が未入力の場合は登録できない。
- 場所の初期値は「お寺」とする。
- 「総代」にチェックがある場合のみ、場所に「自宅」を選べる。チェックがない場合は「お寺」に固定する。
- 登録時に「F-07 予約ルールのチェック」を行い、違反があれば理由を表示して登録しない。
- 登録できたらカレンダーに戻り、登録した予約が表示される。

### 5.4 F-03 法要予約の編集

- 登録済みの全項目を変更できる。
- 日付・時間枠・場所を変更する場合も「F-07」のチェックを行う。このとき、**編集中の予約自身は重複チェックの対象から除く**。

### 5.5 F-04 法要予約の削除

- 削除前に確認ダイアログを表示する（「○月○日 10時 △△様 一周忌 を削除しますか？」）。
- 削除するとカレンダーから消え、その枠は空きになる。
- 本リリースでは物理削除とする（復元機能なし）。

### 5.6 F-05 葬儀の押さえ

- 法要とは **別の種別** として登録する。
- 入力項目は「6.2 葬儀の押さえ」のとおり（最小限の項目のみ）。
- 登録・編集・削除の操作は法要予約と同じ流れで行う。
- 葬儀の詳細（通夜、火葬場、参列者数など）は管理しない。

### 5.7 F-06 施主名検索

- 施主名の **部分一致** で検索する（例：「山田」で「山田太郎」「山田花子」が見つかる）。
- 検索結果は日付の新しい順に一覧表示し、日付・時間枠・施主名・法要の種類・場所・担当を表示する。
- 過去の予約も検索対象に含める。
- 結果から編集画面へ移動できる。
- 該当がない場合は「該当する予約はありません」と表示する。

### 5.8 F-07 予約ルールのチェック

詳細は「7. 業務ルール」のとおり。ルール違反時は、**どのルールに反したか** が分かるメッセージを表示する。

| 違反内容 | メッセージ例 |
| --- | --- |
| 同じ枠に法要がすでにある | 「11月20日 10時枠にはすでに法要の予約があります（△△様 一周忌）」 |
| 同じ日に葬儀の押さえがすでにある | 「11月20日にはすでに葬儀の押さえがあります（13時枠）」 |
| 総代でない施主で場所を「自宅」にした | 「自宅での法要は総代さんのみ登録できます」 |

## 6. データ項目

### 6.1 法要予約

| 項目 | 必須 | 形式・選択肢 | 備考 |
| --- | --- | --- | --- |
| 施主の名前 | ○ | 文字列（最大50文字） | 検索対象 |
| 日付 | ○ | 年月日 | |
| 時間枠 | ○ | 10時 / 11時 / 12時 / 13時 / 14時 / 15時 | 開始時刻。各1時間 |
| 法要の種類 | ○ | 四十九日 / 一周忌 / 三回忌 / 七回忌 / 十三回忌 / 十七回忌 / 二十三回忌 / 二十七回忌 / 三十三回忌 / 五十回忌 / その他 | 確定（百か日・初盆は件数が少ないため「その他」で対応） |

| 項目 | 必須 | 形式・選択肢 | 備考 |

| 日付 | ○ | 年月日 | |
| 時間枠 | ○ | 10時〜15時 | |
| 備考 | - | 自由記述（最大500文字） | |

## 7. 業務ルール（予約の制約）

### 7.1 時間枠

- 時間枠は **10時・11時・12時・13時・14時・15時開始** の6枠（各1時間、最終枠は16時終了）。
- 1件の予約は1つの時間枠のみを使う（複数枠にまたがる予約は本リリースでは扱わない）。
- 予約可能な曜日・定休日・休みの日の制限は設けない（休日設定の機能は作らない）。
- 自宅での法要でも、移動時間のために前後の枠を空ける制限は設けない（法要自体は30分ほどで終わるため）。

### 7.2 制約ルール

| No | ルール | 内容 |
| --- | --- | --- |
| R-1 | 法要は1枠1件 | 同じ日付・同じ時間枠に登録できる法要は **1件まで**。場所（お寺／自宅）に関係なく適用する。 |
| R-2 | 葬儀の押さえは法要と別枠 | 葬儀の押さえは法要とは別に登録できる。葬儀の押さえがある枠でも、**法要を1件** 受けられる。担当が重なっても登録を止めない（住職と副住職が二手に分かれて対応するため）。 |
| R-3 | 葬儀の押さえは1日1件 | 葬儀の押さえは **1日に1件まで**（時間枠が違っても、同じ日には2件目を登録できない）。 |
| R-4 | （削除） | 会場（客殿・観音堂）の項目をなくしたため削除した（2026-11-14）。番号はほかのルールとの対応のため欠番とする。 |
| R-5 | 担当の重複はチェックしない | 同じ枠の法要と葬儀で担当（住職／副住職）が重なっても、システムでは止めない。 |
| R-6 | 自宅での法要は総代のみ | 法要の場所は基本「お寺」。「自宅」は総代が「はい」の予約のみ登録できる。 |

### 7.3 ルールの組み合わせ例（1つの時間枠について）

| 法要 | 葬儀の押さえ | 結果 |
| --- | --- | --- |
| なし | なし | ○ 法要も葬儀も登録できる |
| 1件 | なし | 法要の追加は ×（R-1）／葬儀は ○（R-2） |
| なし | 1件 | 法要は ○（場所は問わない）／葬儀の追加は ×（R-3。同じ日の他の枠も ×） |
| 1件 | 1件 | 法要・葬儀とも追加は × |

### 7.4 同時操作への対応

- 2人の職員がほぼ同時に同じ枠へ登録した場合でも、ルール違反の予約が登録されないこと。
  - 画面での事前チェックに加え、**API（Rails）側で必ずチェック** し、さらに **DBの一意制約** で最終的に重複を防ぐ。
  - 後から登録した側には「F-07」と同じエラーメッセージを返す。

## 8. 非機能要件

### 8.1 システム構成

| 区分 | 採用技術 |
| --- | --- |
| フロントエンド | Next.js + TypeScript |
| バックエンド | Ruby on Rails（APIモード） |
| データベース | MySQL |
| インフラ | AWS（EC2 + RDS for MySQL） |
| 構成管理 | Terraform（インフラはすべてコードで構築する） |

- フロントエンドとバックエンドはJSON形式のREST APIでやり取りする。
- 業務ルール（7章）の最終判定はバックエンドで行う。フロントエンドのチェックは入力補助の位置づけとする。

### 8.2 インフラ

- EC2上でNext.jsとRailsを動かし、DBはRDS（MySQL）を使う。
- RDSはプライベートサブネットに置き、インターネットから直接アクセスできないようにする。
- EC2・RDS・ネットワーク（VPC、サブネット、セキュリティグループ）はTerraformで作成・変更する。手作業での設定変更は行わない。
- RDSの自動バックアップを有効にする（保持期間は7日以上）。

### 8.3 セキュリティ

- 本リリースでは、**アクセス元の制限（IP制限）とHTTPSでの暗号化は行わない**。講師がレビューでアプリを確認できるようにするため、EC2のパブリックIPにHTTP（80番）でアクセスする。
- そのため、IPアドレスを知っている人は誰でも予約を見たり変更したりできる。**本物の檀家さんの個人情報は入力せず、動作確認にはダミーデータを使う。**
- IP制限またはログイン機能、HTTPS化は将来の拡張（11章）で対応する。
- 施主名などの個人情報を扱うため、ログに個人情報を必要以上に出力しない。

### 8.4 性能・使いやすさ

- 月カレンダーの表示は2秒以内を目安とする。
- 電話対応中に操作することを考え、登録は1画面で完結させる。
- 文字は大きめにし、PCのブラウザ（Chrome / Edge 最新版）で使いやすいこと。スマートフォン対応は本リリースでは必須としない。

### 8.5 運用

- 利用者は職員数名、予約件数は年間数百件程度を想定する。
- 日時はすべて日本時間（JST）で扱う。
- 過去の予約は自動で削除せず、保存し続ける（F-04の削除は、キャンセルなど職員が個別に行う場合のみ）。

## 10. 対象外（スコープ外）

本リリースでは次の内容は扱いません。

| 項目 | 備考 |
| --- | --- |
| 葬儀の詳細管理 | 通夜・告別式・火葬場・参列者などの管理。葬儀は「押さえ」のみ登録する。 |
| ログイン機能 | 中級編で追加予定。 |
| アクセス元の制限・HTTPS化 | 本リリースでは行わない（8.3）。 |
| 檀家さん向けの画面・オンライン予約 | 予約は引き続き電話で受け、職員が入力する。 |
| 檀家台帳（檀家さん情報のマスタ管理） | 施主名は予約ごとに入力する。 |
| メール・SMSなどの通知 | |
| 外部カレンダー連携 | Googleカレンダーとの連携・書き出しは行わない（将来の拡張候補）。 |
| 休みの日の設定 | 予約を受けない日を設定する機能は作らない。 |
| データ移行機能 | 既存の予約（紙・Googleカレンダー）は、アプリ完成後に職員が手で入力する。 |
